# SO-101 MuJoCo XML + meshes for ggand0 HIL-SERL

ggand0's `SO101FollowerEndEffector` robot class (in `ggand0/lerobot @
feat/hil-serl`) hard-requires `mujoco_model_path` and loads the model via
`mujoco.MjModel.from_xml_path()`. There is no URDF fallback. The IK is
computed natively from MuJoCo's Jacobians, so we vendor an MJCF model
here.

## What's here

- `so101_new_calib.xml` — the SO-101 robot model. Defines 5 arm joints
  (shoulder_pan, shoulder_lift, elbow_flex, wrist_flex, wrist_roll) + a
  gripper, plus the `gripperframe` and `graspframe` sites that ggand0's
  IK targets. ~70 KB, committed.
- `lift_cube.xml` — scene wrapper that includes `so101_new_calib.xml`
  and adds a free-floating 3×3×3 cm cube body. Useful for sim-side
  experiments; for real-robot IK only the joint kinematics matter so
  either file works as `mujoco_model_path`. We default to
  `so101_new_calib.xml` for the real-robot configs.
- `assets/*.stl` (14 files, ~108 KB total, **committed** because they
  are small) — mesh files referenced by `meshdir="assets"` in the XML.
- `assets/*.part` (14 files) — Onshape-to-robot intermediate files,
  vendored for completeness.

## Provenance

Vendored from `ggand0/pick-101` at HEAD on 2026-05-17:
`https://github.com/ggand0/pick-101/tree/main/models/so101`

The XMLs are themselves generated by [onshape-to-robot](https://github.com/Rhoban/onshape-to-robot)
from the SO-101 CAD at:
`https://cad.onshape.com/documents/7715cc284bb430fe6dab4ffd/w/4fd0791b683777b02f8d975a/e/826c553ede3b7592eb9ca800`

## How it differs from `../so101/urdf/`

The URDF in `../so101/urdf/` is used by lerobot 0.5.2's `RobotKinematics`
(placo-backed). It stays in the repo because:

1. The SmolVLA baseline + sanity pipeline live on lerobot 0.5.2 and use
   the URDF.
2. If we ever want to fall back from ggand0 to a stock-lerobot HIL-SERL
   port, the URDF is needed.

Both representations are kept side-by-side, neither shadows the other.
